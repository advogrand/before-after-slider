# Before / After Image Slider

Чистый HTML, CSS и JavaScript. Без сборки, библиотек, аналитики, логотипов и водяных знаков. На экране только изображения, разделитель и круглая ручка. Подписи изображений доступны скринридеру.

Адрес для этого репозитория: [слайдер](https://advogrand.github.io/before-after-slider/?project=sales), [тестовый пример](https://advogrand.github.io/before-after-slider/?project=demo). В `embed.html` уже указан аккаунт `advogrand`; шаблон с `USERNAME` ниже оставлен для переноса в другой аккаунт.

## Быстрый запуск

Из корня проекта запустите:

```sh
python -m http.server 8000
```

Откройте `http://localhost:8000/?project=sales` — ваши изображения, или `http://localhost:8000/?project=demo` — заменяемый тестовый пример. Без параметра открывается `sales`. Можно также открыть `index.html` напрямую: конфигурация загружается обычным скриптом, без fetch и модулей.

## Изображения и новые проекты

Замените `assets/sales/before.jpg` и `after.jpg` своими файлами либо измените пути в `projects.js`. Сейчас в проекте уже сохранены оба предоставленных JPEG размером **2000 × 1121**. При просмотре сайт не обращается к Dropbox.

Обе картинки должны иметь одинаковые пропорции и совмещённую композицию. Желательно одинаковое разрешение. Слайдер не растягивает и не обрезает картинки; различающиеся пропорции вызывают понятную ошибку вместо неверного сравнения. Неизвестный проект и ошибка загрузки также выводят сообщение. После замены файлов обновите страницу без кеша.

Добавьте папку `assets/interior/` с изображениями и запись внутри объекта `window.SLIDER_PROJECTS`:

```js
interior: {
  title: 'Интерьер',
  before: './assets/interior/before.jpg',
  after: './assets/interior/after.jpg',
  beforeAlt: 'Интерьер до ремонта',
  afterAlt: 'Интерьер после ремонта'
}
```

Разделяйте записи запятыми. Новый URL: `?project=interior`. Используйте короткие имена латиницей. Пути `./assets/...` разрешаются относительно страницы и работают в подпапке репозитория. Не начинайте их с `/assets/`.

## Управление и адаптация

- Начальное положение всегда 50%; слева «до», справа «после».
- Нажатие и перетаскивание мышью или одним пальцем по изображению. За границами области drag продолжается благодаря Pointer Capture.
- Tab фокусирует ползунок; стрелки меняют значение на 1%, Home — 0%, End — 100%. Это нативный range с именем, min/max/value и русским `aria-valuetext`.
- Вертикальный свайп и pinch zoom доступны браузеру. При отмене касания захват сбрасывается.
- Анимация только у оформления ручки; разделитель не движется автоматически. Учитывается `prefers-reduced-motion`.
- Изображения целиком вписываются в ширину **и высоту** окна/iframe. При недостаточной высоте ширина уменьшается; свободное место прозрачно. Это предотвращает обрезку и внутреннюю прокрутку. При подходящей высоте ширина составляет 100%.

## GitHub Pages

1. Создайте публичный репозиторий **before-after-slider** в своём GitHub-аккаунте.
2. Загрузите **содержимое этой папки** в корень репозитория: `index.html` должен быть в корне, а не в дополнительной вложенной папке.
3. Закоммитьте и отправьте файлы в ветку `main`. Например, после инициализации репозитория и добавления remote:

   ```sh
   git add .
   git commit -m "Add accessible before-after image slider"
   git push -u origin main
   ```

4. В **Settings → Pages → Build and deployment** выберите **Deploy from a branch**, `main` и `/ (root)`, затем сохраните.
5. Дождитесь успешного Pages deployment. Адрес: `https://USERNAME.github.io/before-after-slider/?project=sales`.

Если репозиторий называется иначе, замените `before-after-slider` в URL и iframe. Сборка, npm install, GitHub Actions workflow и серверная часть не нужны.

## iframe и Behance

Для репозитория `before-after-slider` замените только `USERNAME` и нужную высоту (в пикселях). Этот же код есть в `embed.html`:

```html
<iframe
  src="https://USERNAME.github.io/before-after-slider/?project=sales"
  width="100%"
  height="810"
  style="border:0; display:block;"
  title="Сравнение презентации до и после"
  loading="lazy">
</iframe>
```

Для ширины 1440 px ваши изображения требуют около 807 px высоты: `высота = ширина × 1121 / 2000`. Для ширины 1200 — около 673 px. Фиксированный iframe не может сам менять высоту внешнего блока Behance: при другом соотношении сторон появится свободное место. Не включайте sandbox без `allow-scripts`, иначе интерактивность не работает.

В редакторе Behance выберите **Embed Media** и вставьте iframe-код, затем проверьте предпросмотр на компьютере и телефоне.

**Ограничение Behance:** техническая готовность страницы к iframe не гарантирует, что Behance примет домен GitHub Pages. В [официальной справке](https://help.behance.net/hc/en-us/articles/204484594-Guide-Embedding-Media) указаны поддерживаемые провайдеры, GitHub Pages среди перечисленных примеров отсутствует. Если редактор отклоняет iframe, обратитесь в поддержку Behance с просьбой разрешить ваш домен либо выберите хостинг, который Behance подтвердит как поддерживаемый. Изменение JavaScript не обходит фильтр провайдеров. Проверка внутри реального проекта Behance требует вашего аккаунта и опубликованного URL; в рамках подготовки файлов она не выполнялась.

## Проверка

Для автоматической проверки нужен Node.js и отдельно установленный **Playwright** с Chromium. Это инструменты разработки, они не подключаются к сайту и не нужны для публикации.

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium
node tests/smoke.cjs
```

При использовании уже установленного Chrome можно задать переменную `BROWSER_PATH` с полным путём к его исполняемому файлу вместо скачивания Chromium.

Тест сам запускает временный HTTP-сервер, проверяет подпапку репозитория, оба проекта, мышь, клавиатуру, touch pointer, границы, размеры iframe и сообщения об ошибках. Для полноценной проверки жестов и скринридеров дополнительно проверьте Safari/iOS и Chrome/Android на реальных устройствах.
